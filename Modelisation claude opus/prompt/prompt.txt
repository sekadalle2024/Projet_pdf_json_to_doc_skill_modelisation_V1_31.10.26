# [CONTEXTE]
- Dossier de travail : **`Modelisation claude opus`**. Il contient :
  1. le script **`excel_to_word.py`** ;
  2. un ou plusieurs fichiers Excel à convertir (.xlsx ou .xlsm).
- Le script convertit le contenu d'un classeur Excel en tableaux Word (.docx), avec la charte graphique du modèle « Matrice de surveillance permanente » :
  - A4 paysage, police Calibri ;
  - en-tête de tableau bordeaux `7B1E3A` avec texte blanc en gras ;
  - première colonne en rose pâle `F2E6EA` ;
  - bordures grises `999999` ;
  - ligne d'en-tête répétée sur chaque page ;
  - lignes qui ne se coupent pas entre deux pages ;
  - en-tête et pied de page avec pagination « Page X / Y ».
- Le script a deux modes de fonctionnement :
  - **`cartographie`** : pour les classeurs de cartographie des risques issus d'une conversion PDF. Ils se reconnaissent à une cellule de la colonne A qui commence par « PROCESSUS / ». Le script produit un tableau par processus, avec un en-tête à deux niveaux (risque inhérent, dispositif de contrôle 1er et 2e échelon, risque résiduel, plan d'actions) et des bandeaux hiérarchiques de sous-processus.
  - **`generic`** : pour tous les autres classeurs. Chaque onglet est lu, les lignes et colonnes vides sont supprimées, et chaque bloc de données séparé par au moins une ligne vide devient un tableau Word. La première ligne du bloc sert d'en-tête.
- Syntaxe : `python excel_to_word.py <entree.xlsx> <sortie.docx> [--titre "Titre"] [--mode auto|cartographie|generic]`
  - Le mode par défaut est `auto` : mode cartographie si le motif « PROCESSUS / » est détecté, sinon mode générique.
  - Dépendances : `openpyxl` et `python-docx`.

# [LIMITES CONNUES DU SCRIPT : À SIGNALER, PAS À CONTOURNER EN SILENCE]
- **Formules** : le script lit les valeurs mises en cache par Excel (`data_only=True`). Si un fichier a des formules jamais calculées (créé par un programme sans ouverture dans Excel), les cellules apparaîtront vides. Signale-le-moi dans ce cas.
- **Mode cartographie** : il suppose une disposition précise des colonnes.
  - Lignes avec libellé d'activité en colonne A : probabilité F, impact G, ampleur H, facteurs I, contrôle 1er échelon K, 2e échelon M, risque résiduel R/S/T, plan d'actions U.
  - Lignes de suite sans libellé : B, C, D, E, J, L, N, O, P, Q.
  - Les lignes de suite sont rattachées au dernier libellé rencontré et affichées avec « ↳ » en gris italique. Ce rattachement peut être inexact si les libellés étaient perdus dans la source.
  - Les colonnes « Conséquences / Impacts » (AA à AH) ne sont pas reprises.
- **Autre disposition de cartographie** : si le résultat est incohérent (colonnes décalées, texte au mauvais endroit, nombre de tableaux anormal), n'essaie pas de corriger toi-même. Décris précisément le problème, avec les coordonnées de cellules, et propose un nouveau mapping `COLS_A` / `COLS_B` dans le script.
- **Mode générique** : il ne gère pas les cellules fusionnées au sens strict (la valeur n'apparaît que dans la cellule en haut à gauche) et n'applique aucune mise en forme conditionnelle. Les classeurs très larges (plus de 10 colonnes) sont rendus en police réduite. Au-delà d'environ 14 colonnes, signale-le-moi, car la lisibilité peut se dégrader.
- **Taille** : un gros classeur donne un gros document (le fichier d'exemple de 783 lignes a donné 115 pages). C'est normal.

| Symptôme | Action |
|---|---|
| `ModuleNotFoundError` | Installe le module manquant (règle 7), puis relance. |
| `PermissionError` à l'enregistrement | Le .docx est probablement ouvert dans Word. Demande-moi de le fermer ou utilise un nom horodaté. |

| Document vide ou très court | Vérifie l'onglet actif et les onglets masqués, puis compare avec l'inventaire. |
| Texte manquant dans le contrôle de complétude | Liste les cellules concernées et cherche la cause (colonne hors mapping, cellule fusionnée, texte trop court). |
